# EXP-003 Results Contract

## Active result files

The runner writes transient/latest outputs to `results/events.jsonl`, `results/summary.csv` and `results/run_metadata.json`. They are Git-ignored and may be replaced by a later run.

## Archive hierarchy

```text
results/
└── archive/
    ├── gate_3a/
    │   ├── ring_control_set_001/<canonical_world_id>/attempt_<NNN>/
    │   ├── solo_control_set_001/...
    │   ├── dyad_set_001/...
    │   ├── bounce_set_001/...
    │   └── ring_control_set_002/, solo_control_set_002/, dyad_set_002/, bounce_set_002/   (replication)
    ├── gate_3b/
    │   ├── diamond_set_001/...
    │   ├── dual_root_set_001/...
    │   ├── solo_control_set_003/...
    │   ├── probe_off_set_001/...
    │   └── diamond_set_002/, dual_root_set_002/                                           (replication)
    ├── gate_3c/
    │   ├── ring_detached_set_001/...
    │   ├── solo_detached_set_001/...
    │   ├── dyad_detached_set_001/...
    │   ├── bounce_detached_set_001/...
    │   └── diamond_detached_set_001/...
    └── gate_3d/
        ├── shared_root_set_001/...
        ├── isolated_shared_root_set_001/...
        ├── dual_root_set_001/...
        └── isolated_dual_root_set_001/...
```

A set executed under a second provider is archived beside the first as `<set>_<provider>` (for example `gate_3a/generalization_set_001_anthropic/`), with the same manifest, seeds and execution order. Its `run_metadata.json` differs from the first set's only in provider and model; `factors.py` verifies this.

`results/preflight/` holds stub executions of a plan (run class `gate_3x_preflight`); it is Git-ignored and never an archive. `gate_3x/campaign_status.json` is a transient pacing record written by the orchestrator and is Git-ignored; closure is established by the corpus audit, not by that file.

Canonical world identity is `E3_<SET_ID>_seed_<SEED>` as printed by the manifest. Each archived attempt must contain `events.jsonl`, `summary.csv`, `run_metadata.json` and `archive_metadata.json`; a technical failure keeps `failure_metadata.json` and reruns the same seed as the next attempt. Archived files are never overwritten. Every archived run receives SHA-256 hashes during its corpus audit.

Sets with different selection schemes (unfiltered versus stratified) are reported separately and never pooled into a single prevalence.
